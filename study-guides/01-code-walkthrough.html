Three identities to keep separate

Token sourceOwns the input shard, gate weights, target, and token loss.
Expert ownerOwns expert parameters. Temporarily computes assignments from many sources.
Shared replicaBlock projection and router copies start equal and receive the same summed gradient.

A rank plays all three roles. “Rank 1 has no expert work” does not mean “rank 1 has no tokens or loss.”

Why does the return exchange use receive, send?

An owner returns one output per received assignment, in the same received row position. Its output chunks go back to the sources that sent them. The original source receives its packed destination chunks again, then undoes its own sort. Reversing split sizes reverses communication; argsort reverses the local packing permutation.

For y = w₁z₁ + w₂z₂ and upstream vector g = ∂L/∂y:

∂L/∂zⱼ = wⱼ g
∂L/∂wⱼ = g · zⱼ
∂L/∂h = expert-input paths + router-input path

The gate weights stay on the source. Selected logits receive gradients through a two-way softmax. Selection indices have no gradient; unselected logits have zero direct gate gradient for that token under this renormalized gate. A top-1 gate normalized to one would eliminate this gate-learning path.

Explain the reverse all-to-all in backward

Across all ranks, an exchange is a reordering of rows, y = Px. The derivative is P, so the adjoint map is Pᵀ: send each output adjoint back to the row's original owner. PyTorch’s differentiable collective stores the split sizes and reverses them in backward. Integer routing metadata uses the plain collective and has no gradient.

training.py · loss() · sync_replicated_gradients()

Derive normalization before choosing a collective

Let ℓᵢ be the mean squared error over token i's 32 output coordinates. N is the total number of tokens across all sources; nᵣ is the local token count.

L = (1/N) Σᵢ ℓᵢ = Σᵣ Lᵣ
Lᵣ = (1/N) Σᵢ∈rank r ℓᵢ
∇θ L = Σᵣ ∇θ Lᵣ

Each shared replica initially has only ∇θLᵣ. A SUM all-reduce gives every copy ∇θL. An expert owner has already processed assignments from every source, with each source loss normalized by N; its gradient already has the correct scale.

At 2 and 6 tokens, the correct gradient is (2×2 + 6×6)/8 = 5. Local means averaged give (2+6)/2 = 4. Globally normalized contributions averaged give 2.5. Equal shard sizes hide the first error, but not the second.

What changes if you replace manual SUM with DDP averaging?

You must reconcile the loss with the averaging divisor. For W shared replicas, multiplying each local contribution by W compensates DDP's average for shared parameters, but it also scales owner-only expert gradients unless their handling changes. Do not globally change the loss without auditing both parameter classes. The current explicit SUM avoids this mismatch.

An empty expert owner still owes two backward exchanges

Consider a hypothetical four-rank route in which all tokens select experts 0 and 1. Rank 0 owns all selected experts. Rank 3 owns experts 6 and 7 and receives zero assignments—but its own source tokens still need experts 0 and 1.

StageRank 0: busy ownerRank 3: empty owner, active source
Dispatch forwardReceives from all sourcesSends its assignments; receives shape [0, 32]
Return forwardSends computed outputs backSends empty chunks; receives outputs for its own tokens
Return backwardReceives output adjointsSends its source-loss adjoints
Dispatch backwardSends hidden-state adjointsReceives adjoints for its projected tokens
Shared syncBoth ranks SUM all-reduce block projection/router gradients in the same order
received = autograd_all_to_all_single(packed.new_empty((sum(receive), packed.shape[1])), packed, receive, send)
computed = received * 0  # graph edge, even for zero rows
# Empty expert calls retain their parameter paths too.
returned = autograd_all_to_all_single(computed.new_empty((sum(send), computed.shape[1])), computed, send, receive)

Zero numerical contribution and no graph dependency are different. Backward needs to reach the dispatch node even when an owner's local expert computation is empty. The zero-valued dependency makes that connection explicit. No branch is allowed to skip a collective because a local row count is zero.

Does this prove zero input tokens on a source are supported?

No. An empty destination is supported by the graph structure but is not forced by the learned-routing checks; an empty source shard is different. The current combine uses reshape(len(x), 2, -1), whose inferred dimension is ambiguous when len(x)=0. Supported commands give every source tokens. See the review guide for the proposed separate test.

60-second explanation to practice

Each rank owns different experts but shares the block projection and router. Tokens choose two experts on their source rank. We pack and send hidden-state assignments to expert owners, compute there, return outputs, and combine them with source-side gate weights. Backward reverses those exchanges. Expert owners already accumulate gradients from all sources, while shared replicas need a SUM because each source contributes only its part of the globally normalized loss. Reference comparisons verify the computation; resource measurements show expert storage shrinking, while this small CPU workload gets slower as communication overhead grows.
